## 배운 내용
qdrant : 벡터를 저장하고 유사도 검색을 해주는 벡터 데이터베이스 / 청크 벡터를 저장하고 쿼리 벡터와 가까운 것을 찾음  

payload : metadata를 담는 곳

UUID5 : 문자열을 입력으로 받아 항상 같은 UUID를 만들어주는 방식 / Qdrant는 포인트의 id로 정수 또는 UUID만 받음  
하지만 청크는 ("travel", 0)처럼 문서 ID와 시작 위치로 식별하여 이걸 UUID로 변경  
변경하는 이유 -> 재실행해도 ID가 같음 / upsert가 중복 저장이 아니라 덮어쓰기로 동작함

upsert : update+insert, 없으면 새로 추가하고, 이미 있으면 덮어쓰는 동작

gte = 이상 / gt = 초과

ANN : 근사 최근접 이웃 / 거의 가장 가까운 것을 빠르게 찾는 검색 방식

point : id + vector + payload  
id : 정수 또는 UUID만 가능  
vector : 384차원 임베딩  
payload : 본문, document_id, metadata 등 검색 결과에 함께 돌려줄 JSON  

청크와 벡터는 같은 행끼리 짝을 짓는것이 중요. chunks[7]과 vectors[7]은 같은 청크  

zip(chunks, vectors) : 같은 위치의 청크와 벡터를 짝지어줌

collection : 같은 벡터 설정을 적용하는 Point 묶음

Query : 질문 벡터와 조건으로 관련 Point를 찾는 요청

limit : 검색에서 반환할 최대 Point 수

필터는 점수에 영향을 주지 않음  
필터는 점수를 매기기 전에 이 청크가 후보가 될 자격이 있는지를 걸러냄  
필터를 만든 것만으로는 아무 일도 일어나지 않고, 검색 요청에 붙여야 적용됨(client.query_points)
