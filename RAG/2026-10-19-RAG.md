## 배운 내용
- RAG : LLM이 답을 만들기 전에 외부 문서에서 관련 정보를 먼저 검색(Retrieval)하고, 그 내용을 프롬프트에 함께 넣어 생성하게 하는 방식

- 80/20 청크(텍스트 조각) : 80자 청크, 20자 겹침

    | |문서 전체 입력|검색 후 입력|
    |---|---|---|
    |장점|검색 담계에서 자료를 놓치지 않음|질문과 관련된 자료로 입력을 줄임|
    |확인할 점|많은 자료에서 필요한 조건을 찾는지|검색이 필요한 문서를 빠뜨리지 않는지|


- RAG, Long Context, CAG의 차이점

    RAG : 근거를 가져오는 방식  
    Long Context : 긴 입력을 처리하는 능력  
    CAG : 공통 자료의 계산 상태를 재사용하는 접근

- 얕은 복사와 깊은 복사의 차이  
    얕은 복사 : 원본과 공유  
    깊은 복사 : 전부 새로 만듦  

    original = {"label": "shipping", "tags": ["배송", "지연"]}  
    얕은 복사는 원본의 tags의 값이 변경되지만, 깊은 복사는 변경 안됨

- repr() : 탭/양끝 공백처럼 안 보이는 글자를 확인

- 연속 공색/탭 정리  
    value : re.sub(r"[ \t]+", " ", line).strip()

- ensure_ascii=False : 한국어를 그대로

- metadata : 본문(content)을 설명하는 부가 정보

## 헷갈린 점 / AI에게 물어본 것
깊은 복사와 얕은 복사의 차이점
|상황|선택|
|---|---|
|값이 문자열/숫자뿐인 평평한 구조, 또는 바깥 키만 교체|얕은 복사|
|안쪽 리스트/딕셔너리를 직접 수정할 때|깊은 복사|
|원본을 절대 건드리면 안 되는 중첩 데이터|깊은 복사|  
깊은 복사는 전부 새로 만들어서 느리고 메모리를 더 씀 

footer : 문서나 페이지의 맨 아래에 반복해서 들어가는 영역(바닥글, 하단 표기)  
header : 제목  
splitlines() : 문자열을 줄바꿈 기준으로 잘라 리스트로 만듬 / split(". ")로 문장을 나눈 것의 줄 버전
"\n".join(kept) : 남긴 줄들을 줄바꿈으로 이어 붙여 문자열 하나로 만듬
