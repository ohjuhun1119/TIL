## 배운 내용
청크 : 일정한 크기로 자른 텍스트 조각  

토큰 : 모델이 텍스트를 처리하는 최소 단위 / 단어보다 작은 조각

토큰 벡터 : 이 토큰 하나하나를 숫자 수백 ~ 수천개짜리 배열로 바꾼 것

임베딩 모델 : 텍스트를 넣었을 때 그 의미를 담은 벡터를 내보내는 모델

pooling : 여러 개의 토큰 벡터를 하나로 합치는 작업

청크 벡터 : pooling의 결과물로 청크 하나의 의미 전체를 대표하는 벡터 한 개 

코사인 유사도 : 두 벡터가 가리키는 방향이 얼마나 비슷한지

top-k : 유사도가 높은 순서로 k개를 가져오는 것

청크(텍스트) → 토큰들 → 토큰 벡터들 → pooling → 청크 벡터 1개 

threshold : 임계값 기준을 넘으면 통과, 못 넘으면 탈락  
너무 높으면 필요한 청크까지 거르고 너무 낮으면 필터를 못함

### RAG 전체 흐름 정리  
[미리 해두는 단계: 인덱싱]  
1. 문서 → 청크로 분할 (+ 제목, 출처 같은 메타데이터 부착)  
2. 청크 텍스트 → 임베딩 모델 → 토큰 벡터들 → pooling → 청크 벡터 1개  
3. 청크 벡터를 벡터 DB에 저장  

[질문이 들어올 때: 검색 + 생성]  
4. 질문을 같은 임베딩 모델로 벡터화 (쿼리 벡터)  
5. 쿼리 벡터와 청크 벡터들의 코사인 유사도 계산  
6. 유사도 상위 k개 청크 선택  ← 여기까지가 Retrieval  
7. 질문 + 선택된 청크를 하나의 프롬프트로 조립  ← Augmentation  
8. LLM이 프롬프트를 읽고 답변 생성  ← Generation
