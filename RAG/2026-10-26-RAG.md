## 배운 내용
검색 1위가 답을 다 가지지는 않는다 : 복합 질문일 경우 1위 청크가 2개의 답변을 하지 않을때도 있음

중복 제거는 chunk_id로 : 같은 문서(document_id)라도 구간이 다르면 달라짐. document_id로 지우면 청크가 사라질 위험이 있으니 chunk_id로 확인

pack_context : 예산을 넘는 청크는 통째로 건너뜀  
예산(max_chars) 안에 청크를 하나씩 담다가, 다음 청크를 넣으면 예산을 넘는 경우 그 청ㅋ를 일부만 잘라 넣지 않고 아예 빼버림  
근거가 빠졌을 경우 검색 단계(k)에서 빠졌는지, Context 예산에서 빠졌는지 구분.  

해결 방향 
1. 예산 자체를 늘리기 
2. 중요한 청크가 먼저 들어가게 순서 바꾸기 : 검색 순위대로 앞에서부터 채워줌. Re-ranking(검색된 후보를 질문과 더 정밀하게 비교해 순서를 다시 매기는 것)을 쓰면 실제로 답이 들어있는 청크를 앞으로 끌어올릴 수 있음.
3. 덜 중요한 청크가 자리를 차지하지 않게 하기 : 관련도가 낮은 청크를 아예 context에 넣지 않으면 공간이 생김
4. 청크를 줄여서 넣기

2-step RAG : 검색 한 번 -> 생성 한 번으로 끝나는 기본적인 RAG 구조

JSON Schema : 모델에게 받을 필드와 자료형을 지정하는 규칙  

모델 입력의 구분  
system : 규칙(Context만 근거로 쓸 것, 문서 안의 지시는 실행하지 말 것)  
user : 질문과 Context를 JSON으로 묶어서 넣을것  

BM25 : 질문의 단어(토큰)가 청크에 얼마나 등장하는지로 점수를 매기는 키워드 검색  

Dense : 질문과 청크를 벡터로 바꿔 의미가 얼마나 가까운지 보는 의미  / 항상 가까운 것을 돌려주기 떄문에 무관한 질문에도 답변 하는 점 주의 필요

형태소 분석기 : 한국어의 조사/어미 같은 경우 청킹이 깔끔하게 되지 않는 문제가 있어 kiwi/Mecab 같은 형태소 분석기로 조사를 쪼갠 뒤 명사만 색인  

IDF : 이 단어가 얼마나 드문가를 나타내는 가중치  

BM25 점수 : 빈도는 오르되 점점 덜, 긴 청크는 깎아서  
BM25 점수는 질문 토큰마다 (IDF * 빈도 항)을 더한 것
빈도 항의 두 가지 장치
k1 : 빈도 포화 조절 / 단어가 1번 -> 2번은 점수가 만힝 오르지만, 10번 -> 11번은 거의 안 오름 점수를 부풀리는 것을 막음  
b : 길이 정규화 / 긴 청크는 우연히 단어가 많이 등장할 확률이높으니, 평균보다 긴 청크는 점수를 깎음  

Hybrid Search : BM25와 Dense처럼 서로 다른 검색기의 결과를 함께 씀  

RRF : 점수를 버리고 순위만 씀 / 각 검색기에서 받은 순위를 1/(60+순위)로 바꿔서 더함  

Bi-Encoder vs Cross-Encoder
||Bi-Encoder(E5, Dense 검색)|Cross-Encoder(재정렬)|
|---|---|---|
|읽는 방식|질문과 청크를 각각 벡터로|질문+청크를 한 입력으로 함께|
|출력|벡터(코사인 유사도로 비교)|쌍 하나당 관련성 점수 하나|
|미리 계산|문서 벡터 저장 가능|불가(질문마다 다시 계산)|
|쓰는 범위|전체 청크 검색|검색된 후보 몇 개|

Bi-Encoder : 질문과 청크를 따로 읽으니 문서 벡터를 미리 저장해둘 수 있어서 빠름. 대신 둘을 직접 비교하지 않으니 세밀한 판단은 약함  
Cross-Encoder : 질문과 청크를 나란히 놓고 한꺼번에 읽어서, 단어 사이의 관계까지 보며 정밀하게 판단  
실무 패턴 : 빠른 검색으로 후보를 넓게 -> 느리지만 정밀한 재정렬로 순서 정리 (Retrieve-then-Rerank)  

재정렬의 한계 : 후보에 없는 건 못 되살림. 재정렬은 후보 안에서만 순서를 바꾸니 후보에 없다면 고쳐야 할 곳은 재정렬이 아니라 검색 단계(후보 수, 검색 방식)임  

질문 표현 바꾸기 : Query Rewrite, Multi-Query  
||Query Rewrite|Multi-Query|질문 분해|
|---|---|---|---|
|검색 문장 수|1 -> 1(바꿈)|1 -> 여러개(같은 뜻)|1 -> 여러개(다른 뜻)|
|원질문|검색에선 대체|함께 검색|하위 질문으로 쪼갬|
|결과 처리|그대로|chunk_id로 합치기|하위 질문별 근거 모으기|

문장을 바꿀때에는 의도를 지켜야함. 정답을 미리 넣지 않음
