### LoRA 어댑터 학습과 모델 복원
전체 파인튜닝 (Full Fine-Tuning)
- 모델의 모든 가중치를 학습으로 갱신하는 방식  
- 학습할 때 가중치 말고도 기울기와 optimizer상태를 같이 저장해야 해서, 메모리가 추론할 때의 약 4배 듬.

PEFT (Parameter-Efficient Fine-Tuning)
- 일부 파라미터만 학습해서 메모리와 저장 비용을 줄이는 방법들을 묶어 부르는 이름
- LoRA는 PEFT에 속한 방법 중 하나  

|용어|답하는 질문|
|---|---|
|SFT|무엇을 정답으로 배우나(학습 목표 : 입력 + 모범답안)|
|LoRA|어떤 파라미터를 학습하나 (학습 대상)|
|QLoRA|고정한 기반 가중치를 어떻게 작게 저장하나|
|PEFT|이를 어떤 도구로 적용하나|

### 저랭크 업데이트를 행렬로 이해하기
가중치 행렬 W
- 신경망의 층은 숫자 표로 되어 있고, 입력 x에 곱해서 출력을 만듬(W@x)  
- 크기가 [출력, 입력]인 표라서, 입력과 출력이 크면 숫자사 수십만 ~ 수백만 개  

변화량 ΔW
- 학습이 끝난 가중치 = 원래 W + ΔW. 학습의 결과를 "얼마나 고쳤나"라는 표 하나로 볼 수 있음.  
- 전체 파인튜닝은 ΔW의 모든 칸을 자유롭게 학습.  

랭크와 저랭크  
- 랭크는 행렬이 가진 독립적인 정보의 개수. 큰 표라도 구조가 단순하면 랭크가 작음
- 랭크가 r인 행렬은 [출력, r] 표와 [r, 입력] 표의 곱으로 쓸 수 있음.  
- 1000x1000 표는 숫자가 100만개지만, 랭크 8이면 1000x8 표와 8x1000 표의 곱으로 표현되어 숫자가 1만 6천개(8x(1000+1000))로 줄음.  

저랭크 업데이트 : 변화량 w를 "얇은 두 표의 곱"으로만 만들도록 제한하고, 그 두 표만 학습하는 방법.  

LoRA의 핵심 가정
- 파인튜닝에서 생기는 변화량 ΔW는 저랭크로 충분히 표현된다는 가설에 기대로 있음, 그래서 ΔW를 처음부터 "얇은 두 표의 곱"으로 제한하고, 그 표만 학습.

### LoRA의 구조
A, B, r, alpha
- A : [r, 입력] 표 : 입력을 r차원으로 줄임.
- B : [출력, r] 표 : 줄어든 값을 출력 크기로 되돌림.
- r(랭크) : A와 B 사이의 중간 차원. 클수록 표현할 수 있는 변화가 다양해지지만 학습 파라미터가 r에 비례해서 늘어남.
- alpha : 옆길 출력에 곱하는 배율의 분자. 실제 비율은 alpha/r

식  
h = W·x + (alpha / r) · B · A · x  

파라미터 수 공식  
- 한 선형층의 LoRA 파라미터 = r x (입력+출력)  
- r을 2배로 하면 학습 파라미터도 2배가 됨.  

alpha/r 배율 쓰는 이유
- r을 바꿔도 변화량의 크기가 크게 달라지지 않게 맞춰서, r을 바꿀 때마다 학습률을 다시 조정하는 부담을 줄여줌.  
- r만 바꿔도 배율이 바뀌므로 r과 alpha는 따로 읽어야 함.  

초기화 (B=0)
- B를 0으로 시자하면 학습 시작 시점에 옆길 출력이 0이라, 모델이 원래 모델과 정확히 같은 상태에서 출발함.
- A와 B를 둘 다 0으로 두면 안됨. 두 표가 서로의 값에 곱해져서 기울기가 둘 다 0이 되고 학습이 시작되지 않음.  
- A만 무작위로 두고 B=0이면, 첫 스텝에서는 A의 기울이가 0이고 B만 갱신.

### LoraConfig 항목들
LoraConfig : LoRA 방식으로 모델을 미세 조정할 때 설정을 담는 개체. LoRA를 모델의 어느 부분에 어떤 크기로 적용할지 정함.  

target_modules (어디에 붙일까)
- LoRA 옆길을 붙일 층의 이름 목록
- Transformer의 Attention에는 q_proj, k_proj, v_proj, o_proj(qurey, key, value, outpyt 투영)가 있고, MLP에는 gate_proj, up_proj, down_proj가 있음.  
- Attention 한 줄 요약 : query는 "내가 찾는 것", key는 "각 토큰의 이름표", value는 "실제로 가져올 내용"  

lora_dropout
- 학습 중 LoRA 옆길의 입력 일부를 무작위로 꺼서 과적합을 줄이는 규제  

bias
- 층의 bias(편향) 항을 학습할지 정함. none이면 학습하지 않음.  

task_type
- 어떤 용도의 PEFT 구성인지 정함. 다음 토큰을 생성하는 언어 모델이면 CAUSAL_LM

base_model_name_or_path, revision
- 이 어댑터가 어느 기반 모델용인지 기록해 두는 항목. 나중에 복원할 때 맞춰야 함.

### PEFT로 붙이고 확인하기

freeze(고정)와 requires_grad
- 파라미터마다 requires_grad가 True면 기울기를 계산하고 optimizer가 갱신. False면 고정이라서 기울기도 optimizer 상태도 만들지 않음. 이것이 LoRA의 메모리 절약 원리.

get_peft_model
- 기반 모델에 LoRA 옆길을 붙여주는 함수. 호출만으로 학습이 끝나는 게 아님.

붙인 뒤 확인해야 할 것
- 학습 대상(requires_grad=True)이 LoRA 이름 뿐인지 : 기반 가중치가 섞이면 사실상 전체 파인튜닝이 됨.
- 학습 전에는 B가 모두 0인지, 학습 뒤에는 B가 0인지, 기반 W가 그대로인지.

LoRA의 학습률
- LoRA는 전체 파인튜닝보다 더 큰 학습률을 쓰는 경우가 흔함.
- 그래서 전체 파인튜닝의 학습률을 그대로 쓰면 LoRA는 거의 안 움직일 수 있음.

### 어댑터 저장, 복원, 병합
어댑터
- 기반 모델에 끼워 쓰는 추가 학습 부분. 혼자서는 언어 모델이 되지 않음.

save_pretrained
- 어댑터의 가중치와 설정만 저장. 기반 모델은 저자하지 않아서 크기가 수 MB 수준.  

PeftModel.from_pretrained
- 같은 기반 모델을 먼저 올리고 그 위에 어댑터를 끼움.
- 기반 모델의 ID, revision, dtype이 다르면 어댑터가 다른 W 위에 더해져서 의미 없는 출력이 나옴.
- is_trainable=False는 추론용으로 읽는 것, True는 이어서 학습할 때

병합(merge_and_unload)
- 옆길의 변화량을 W에 미리 더해서 하나의 일반 모델로 만듬. 

|배포 방식|장점|단점|
|---|---|---|
|기반+어댑터|업무별 어댑터를 바꿔 끼움, 저장이 작음|추론 때 옆길 계산이 조금 더 듦|
|병합|일반 모델과 같은 속도, 서빙 도구와 호환|어댑터마다 전체 모델 크기로 저장|

수치 검증 : allclose, atol, rtol
- 부동소수점 계산은 반올림 오차가 있어서 ==로 비교하면 안됨.
- 허용 오차는 수치가 같은지에 대한 것이지, 업무 답의 오답을 허용한다는 뜻이 아님. 숫자는 allclose로, 생성 원문은 ==로 따로 확인

### 공정하게 비교하는 법
통제 변인
- 두 방법을 비교하려면 비교하려는 한 가지만 다르게 두고 나머지는 전부 길게 맞춰야 함.
- 주의 : 그 "같게 둔" 조건이 한쪽 방법에 불리할 수 있음. 예를 들어 전체 파인튜닝용 학습률로 LoRA를 학습하면 LoRA가 못한다고 잘못 결론 내릴 수 있음.
