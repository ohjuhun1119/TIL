## QLoRA

### 양자화
정의
- 정밀한 숫자를 몇 개의 대표값 중 하나의 번호로 바꿔 저장해서 용량을 줄이는 기법 
- 번호를 저장하고, 쓸 때 대표값으로 복원. 복원한 값은 원래 값과 조금 다른 근삿값

scale(크기 조절값)
- 원래 값의 범위를 대표값의 범위에 맞추기 위한 배율. 보통 블록 안의 최대 절댓값을 씀.

압축
- 서로 다른 값이 같은 대표값으로 합쳐지기 때문에 세밀한 차이를 잃음. 이 오차가 양자화 오차

블록 단위(block-wise) 양자화
- 가중치를 일정 개수의 블록으로 나누고 블록마다 sclae을 둠. 큰 이상값 하나가 전체 정밀도를 망치는 걸 한 블록 안으로 막아 줌.

### NF4와 이중 양자화
NF4 (4-bit NormalFloat) : QLoRA에서 쓰는 4비트 양자화 형식
- 4비트라서 대표값이 2^4 16개
- 학습된 가중치는 0 근처에 몰린 종 모양(정규분포에 가까운) 분포를 보이는 경우가 많아서, NF4는 대표값을 0 근처에 촘촘하게 배치. 값이 많은 곳에 눈금을 더 세운다는 발상

이중 양자화
- 블록마다 둔 sclae 자체를 한번 더 양자화해서(8비트) 저장 공간을 아끼는 기법.
- 가중치를 두 번 압축하는게 아님. 두 번째 압축 대상은 scale

### 저장 정밀도와 계산 정밀도는 따로
자료형 정리
|자료형|크기|특징|
|---|---|---|
|FP32|32비트|정밀하고 안정적, 메모리 큼|
|BF16|16비트|FP32와 같은 표현 범위, 유효 숫자는 적음. 지원하는 GPU에서 학습에 널리 쓰임|
|FP16|16비트|표현 범위가 좁아 학습 시 손실 스케일링 같은 보정이 필요|
|NF4|4비트|저장용. 계산에는 직접 못 쓰고 풀어서 사용|
- 일부 GPU는 BF16을 하드웨어로 지원하지 않아서 FP32로 돌려야 함.

저장 vs 계산
- 저장 형식 : 가중치를 보관하는 방식 (NF4 번호 + scale) 
- 계산 정밀도(compute dtype) : 행렬 곱을 할 때 쓰는 정밀도
- 계산할 때마다 4비트 번호를 근삿값으로 풀어서 곱함. 4비트끼리 곱하지 않음.

### 메모리는 어디서 쓰이고, 누가 무엇을 줄이나 
|덩어리|줄이는 방법|
|---|---|
|모델 가중치|양자화(저장 비트를 낮춤)|
|기울기+optimizer 상태|LoRA(학습 파라미터 수를 줄임)|
|활성값(중간 계산값)|gradient checkpointing (필요할 때 다시 계산)|
|임베딩 등 양자화 안 된 부분|줄 지 않음|
- 양자화와 LoRA는 서로 대신할 수 없고, 줄이는 곳이 다름. QLoRA는 둘을 함께 씀
- gradient checkpointing은 메모리를 시간과 맞바꾸는 기법. 학습 체크포인트와는 이름만 비슷한 다른 기능

### QLoRA 학습 준비
QLoRA
- 기반 가중치를 NF4로 압축해서 고정하고, 그 옆에서 LoRA만 고정밀로 학습
- 학습 목표는 여전히 SFT. QLoRA는 새 손실 함수의 이름이 아니라 저장 방식을 바꾼 LoRA
- 기울기는 압축한 근사 가중치 계산을 통과하지만, 그 가중치를 고치지는 않음

BitsAndBytesConfig
- 이 모델을 이렇게 4비트로 읽어 달라는 주문서
- 값 하나만 바뀌어도 근사된 가중치가 달라지므로, 설정을 통째로 기록해 두어야 재현됨.  

prepare_model_for_kbit_training
- 4비트 모델을 학습하기 전에 부르는 준비 함수.   
    - 기반 가중치를 전부 고정
    - 양자화되지 않은 층(임베딩,Norm 등)을 FP32로 올려 학습 안정성 확보
    - gradient checkpointing을 켬
- 순서가 중요함. prepare -> get_peft_model 순서여야 함. 반대로 하면 새로 붙인 A*B까지 얼어 붙을 수 있음.

QLoRA는 항상 이득일까
- 기반 모델이 클수록 선형층의 비중이 커서 메모리 절감 효과가 큼.
- 모델이 작으면 양자화 안 된 부분(임베딩 등)이 차지하는 비중이 크고, 풀어서 계산하는 오버헤드 때문에 속도가 더 느려지거나 최대 메모리가 줄지 않을 수 있음.
- LoRA로 메모리에 들어가면 LoRA, 안들어갈 때 QLoRA가 기본 판단.

paged_optimizer
- QLoRA 논문이 쓰는 기법으로, optimizer 상태가 GPU 메모리 순간 급증으로 터지지 않게 CPU 메모리로 넘기는 방식.

복원
- 어댑터 파일만으로는 모델이 아님. 같은 기반 모델 + 같은 양자화 설정 + 같은 준비 과정이 있어야 같은 결과가 나옴.
- 순서 : NF4로 로드 -> prepare -> 어댑터 부착(is_trainable=False) -> 출력 비교
- 추론을 다시 만드는 것이어서, optimizer 상태가 없어 학습 재개용 체크포인트가 아님. 
- 정밀도(BF16/FP32)가 다른 환경에서는 복원이 어긋날 수 있어, 학습과 복원은 같은 종류의 GPU에서 하는게 안전함.

### 평가할 때 주의
손실(loss) ≠ 업무 정답률
- SFT 손실은 정답 토큰들의 평균 오차. 몇 개 토큰만 플려도 전체 평균은 거의 0에 가까울 수 있어서 손실이 낮아도 중요한 오답이 남을 수 있음.
- 그래서 손실과 별개로 생성된 원문을 직접 읽고 채점해야 함.

형식 통과 ≠ 판단 맞음
- 형식 검사는 JSON 구조, 필드, 인용 ID가 규칙을 지켰는지만 확인
- 형식이 완벽해도 내용(금액 비교, 승인 여부 등)은 틀릴 수 있어서 둘을 따로 봄

같은 0점도 이유가 다름
- 실패 원인(필드 누락, 형식 위반, 인용 오류 등)을 유형별로 분류하면 다음에 무엇을 고칠지 보임

표본 수가 작으면 결론을 조심
- 평가 문항이 12개면 1문항이 8% 이상. 한 번의 실행 결과는 관찰이지 일반 성능이 아님
