## 프롬프트/RAG/파인튜닝 차이점
| |프롬프트|RAG|파인튜닝|
|---|---|---|---|
|바꾸는 곳|지시 텍스트|근거 문서|가중치|
|해결하는 문제|형식/지시|지식|반복되는 행동 실패|
|비용|거의 없음|검색 저장소 운영|데이터+GPU|
|수정 속도|즉시|문서만 교체|재학습 필요|

## 학습 방법
학습 목표(무엇을 정답 신호로 쓰나) : SFT, DP  
학습 대상(어떤 숫자를 바꾸나) : 전체학습, LoRA, QLoRA 

SFT(Supervised Fine-Tuning, 지도 미세조정) 
- 질문 하나에 모범답안 하나를 보여주고, 그 답을 그대로 따라 하게 학습
- 방식 : 모범답안 토큰의 확률을 올리도록 손실을 계산
- 쓰는 곳 : "이런 입력엔 이런 출력"이라는 정답 예시를 만들 수 있을 때
- 한계 : 정답을 베끼는 학습이라, 형식이 맞아도 의미는 틀릴 수 있음

DPO(Direct Preference Optimization, 직접 선호 최적화)
- 정답 하나가 아니라 좋은 답과 나쁜 답을 비교해서, 좋은 쪽의 상대 점수가 높아지게 학습
- 방식 : 같은 질문에 대한 답 두 개를 짝지어 주고, "이 답이 저 답보다 낫다"는 선호를 학습
- 쓰는 곳 : SFT 이후에 "이런 답은 하지 마"를 가르치고 싶을 때. ex) 근거가 없는데 답한ㄴ 환각을 나쁜 답(rejected)으로 줌.
- 한계 : 선호 상 데이터를 따로 만들어야 함

LoRA(Low-Rank Adaptation)
- 원래 가중치 W는 고정하고, 작은 보조 행렬 B*A만 학습
- 방식: 큰 행렬을 통째로 바꾸는 대신, 작은 두 행렬의 곱(B*A)으로 "변화량"만 표현해서 W에 더함.
- 장점 : 기울기와 AdamW 상태(파라미터당 2개)를 0.1%에 대해서만 들고 있으면 되니 메모리가 크게 줄어듬.
- 참고 : "LoRA로 SFT를 한다"가 맞는 표현

QLoRA(Quantized LoRA)
- LoRA인데, 고정된 W를 4비트(NF4)로 압축해서 저장
- 방식 : 어짜피 안 바꾸는 W를 4비트로 줄여 메모리를 아끼고, 학습되는 B*A는 LoRA 그대로 학습. 학습 목표는 SFT 그대로
- 장점 : GPU로 더 큰 모델을 다룰 수 있음
- 한계 : 압축해서 오는 약간의 정밀도 손실이 있고, 압축과 복원 때문에 속도가 조금 느릴 수 있음.

학습이란
- 모델은 토큰 ID를 읽고, 다음 토큰의 확률 분포를 내놓음. 정답 토큰의 확률이 낮을수록 손실이 크고, 기울기(p-y)가 "어느 방향으로 얼마나 틀렸는지"를 알려줌. 가중치를 그 반대 방향으로 조금씩 옮기는 것이 학습.

## 토큰 확률과 가중치 갱신
### 토큰과 토크나이저  

모델은 글자가 아니라 토큰 ID를 읽음. 토크나이저가 텍스트를 토큰으로 쪼개고 ID로 바꿈. 토큰은 자주 나오는 바이트 묶음이라서 단어 수나 글자 수와 다름.  

숫자는 한 자리씩 쪼개짐. 그래서 모델은 금액 비교를 숫자 크기가 아니라 토큰 순서로 배움.  

깨져 보이는 토큰은 한글 UTF-8 바이트를 글자로 표시한 것이고, decode하면 원래 글자로 돌아옴.  

비용, 지연, 컨텍스트 한도, 학습 길이는 모두 토큰 기준.  

### apply_chat_template  

모델은 학습 때 본 제어 토큰 순서로 역할(system, user, assistant)을 구분.  

문자열을 손으로 이어 붙이지 않고 apply_chat_template이 이 형식을 만들어 줌.  

add_generation_prompt=True는 끝에 assistant 시작 표시를 붙여서 "여기서부터 답하라"는 위치를 알려줌.

|인자|하는 일|실무에서 볼 점|
|---|---|---|
|add_generation_prompt|끝에 assistant 시작 표시 추가|추론 입력 True : 정답이 들어간 학습 대화 False|
|return_dict/return_tensors|input_ids+attention_mask를 텐서로|model.generate(**inputs)로 바로 넣기|
|(모델 계열)|Qwen <im_start>|모델을 바꾸면 템플릿부터 바뀜|

### 학습 1스텝
로짓 -> softmax 확률 -> 손실(교차엔트로피) -> 기울기 -> 갱신  

softmax : 점수를 합이 1인 확률로 바꿈  

교차엔트로피는 정답에 준 확률이 낮을수록 손실이 커짐  

p - y : 손실 L=-log p_y를 점수 s로 미분하면 p-y가 됨. 부호는 방향이고, 크기는 얼마나 틀렸나를 의미함. 가중치의 기울기는 (뒤에서 온 오차) * (그 가중치에 들어온 입력)이라는 연쇄법칙으로 구함.  

SGD(Stochastic Gradient Descent, 확률적 경사 하강법)
- 기울기가 가리키는 반대 방향으로, 기울기 크기에 비례해서 가중치를 옮기는 가장 기본적인 방법
- 갱신식 : θ <- θ - lr*g (θ는 가중치, g는 기울기, lr은 학습률)  
    1. 기울기가 크면 많이 움직이고, 작으면 조금 움직임
    2. 모든 가중치에 같은 학습률을 씀
    3. 추가로 저장할 값이 없어서 메모리가 가장 적게 듬
    4. "확률적"은 전체 데이터가 아니라 일부 데이터로 기울기를 추정한다는 뜻

AdamW
- 가중치마다 보폭을 자동으로 조절하는 방법 요즘 LLM 학습에서 기본값
- 갱신식 : θ <- θ − lr · m/√v (보정 포함)
    1. m은 기울기의 이동 평균으로, 최근 기울기가 가리키던 방향을 기억함
    2. v는 기울기 제곱의 이동 평균으로, 그 가중치의 기울기가 보통 얼마나 큰지를 기억함.
    3. 기울기를 v로 나눠서 정규화하기 때문에, 기울기가 원래 큰 가중치는 보폭을 줄이고 작은 가중치는 상대적으로 키움.

| |SGD|AdamW|
|---|---|---|
|갱신|θ − lr·g|θ − lr·m/√v (보정)|
|첫 걸음|기울기에 비례|파라미터당 2개|
|추가 메모리|0|파라미터당 2개|
|흔한 lr|-|전체 1e-5대/LoRA 1e-4대|

부가 설명 : AdamW는 기울기르 정규화하기 때문에 첫 걸음에서 모든 가중치가 대햑 lr만큼 움직임. 대신 파라미터마다 상태값 m, v를 더 들고 있어야 해서 메모리를 더 씀.

generate 결과 : 입력 + 새 토큰  
generate는 입력 뒤에 새 토큰을 이어 붙여 돌려주므로, 입력 길이 이후만 새 답으로 읽어야 함.
