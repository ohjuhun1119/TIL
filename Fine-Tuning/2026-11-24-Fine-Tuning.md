## DPO의 기본 개념

선호 학습(preference training)
- 모델에게 "정답 하나"를 보여주는 대신 "두 답 중 이쪽이 더 낫다"는 비교 정보를 주고 배우게 하는 방식
- 정답을 일일이 쓰기 어렵지만 "둘 중 뭐가 낫냐"는 고르기 쉬운 상황에 잘 맞음

SFT와 DPO의 차이
| |SFT|DPO|
|---|---|---|
|데이터|입력+모범답안 1개|입력+좋은 답+나쁜 답|
|가르치는 것|이 답을 따라 해라|이 답이 저 답보다 낫다|
|손실의 기준|정답 토큰 확률|기준 모델보다 두 답의 격차가 벌어졌나|

DPO (Direct Preference Optimization)
- 선호 쌍으로 모델을 직접 학습시키는 방법. 이름의 "Direct"는 중간 단계가 없다는 뜻
- DPO는 무엇을 목표로 배우나(학습 목표), LoRA, QLoRA는 어떤 파라미터로 배우나(학습 대상). 

SFT 뒤에 하는 이유
- 모델이 형식과 기본 행동을 SFT로 먼저 익혀야, 그 위에서 판단의 질만 다듬는 비교 학습이 의미가 있음. DPO는 보통 SFT를 마친 모델에서 출발

### 선호쌍 만들기
선호쌍(preference pair)
- 같은 입력(질문+근거)에 대한 답 두 개를 짝지은 데이터
- 구성:prompt(입력), chosen(더 나은 답), rejected(덜 나은 답)

좋은 선호쌍의 조건
- 입력이 같아야 함. 입력이 다르면 비교가 성립하지 않음
- 잘못을 하나씩만 넣음. rejected가 형식도 틀리고 판단도 틀리면, 모델이 무엇을 피해야 하는지 모름. 형식을 둘 다 맞고 판단만 다르게 만들면 "판단의 차이"를 배움
- 선호 이융를 한 문장으로 쓸 수 잇어야 함. 이유를 못 쓰는 쌍은 좋은 쌍이 아님
- rejected는 모델이 실제로 낼 법한 그럴듯한 오답일수록 학습 신호가 유용하다고 알려져 있음. 이미 하지도 않는 엉뚱한 오답은 배울게 적음

양쪽 방향의 오류를 다 넣는다
- 한쪽 오류만 벌하면 모델이 반대쪽으로 치우침
    - 과잉 보류(답할 수 있는데 답을 거부)만 벌하면 -> 근거 없이 단정하는 쪽으로 감
    - 근거 없는 단정만 벌하면 -> 무조건 보류하는 쪽으로 감
- 그래서 보류해야 할 때, 답해야 할 때 답의 양쪽 오류를 모두 rejected로 넣어 균형을 맞춤

선호 라벨이 틀리면 틀린 신호도 그대로 배운다
- DPO는 라벨을 의심하지 않고 따라감. 데이터의 chosen/rejected 판정 자체를 사람이 검수해야 함

## DPO의 수식 읽기 (logp -> reward -> margin -> loss)
policy와 reference
- policy : 학습 중인 모델. 가중치가 계속 바뀜
- reference(기준 모델) : 학습 전의 모델을 고정해 둔 것. 시작할 때는 policy와 같고, 이후에는 policy만 변함.

기준을 고정하는 이유
- 선호를 따라가다 모델이 원래 상태에서 너무 멀리 벗어나는 걸 막는 닻 역할을 함.

기준 점수를 미리 계산
- reference의 점수는 학습 전에 한 번 계산해서 숫자로 보관. 그러면 학습 중에는 policy 모델만 GPU에 올리면 돼서 메모리를 아낄 수 있음

dropout은 꺼둠
- dropout이 켜져 있으면 같은 모델도 호출할 때마다 점수가 달라져서 기준 점수가 흔들림. 점수를 비교하는 학습에서는 dropout 0으로 고정.

### logp
logp (로그 확률)
- 확률에 로그를 취한 값. 확률이 1이면 0, 확률이 낮을수록 큰 음수가 됨.
- 로그를 쓰는 이유 : 확률은 곱하면 값이 너무 작아지는데, 로그를 취하면 곱이 합이 되어 다루기 쉬움

답 하나의 점수 = 답변 토큰 logp의 합
- 모델이 답을 만드는 확률은 "각 토큰 확률의 곱"이고, 로그에서는 토큰별 logp의 합이 됨.
- 프롬프트와 패딩 위치는 -100으로 빼고, 답변 +EOS 토큰만 더함

합 vs 평균 : 길이가 점수에 들어감
- 같은 토큰당 확률이라도 답이 길수록 합은 더 작아짐
- 그래서 합 대신 평균으로 바꾸면 다른 목적함수가 됨. 두 답의 길이가 다르면 길이 자체가 점수 차이에 영향을 줌

logp의 값을 읽는 법
- 합이 0에 가까우면 -> 그 답을 모델이 거의 확실하게 낸다는 뜻
- 합이 크게 음수면 -> 그 답을 낼 확률이 매우 낮다는 뜻
- 토큰당 평균 확률=exp(합+토큰 수)(기하평균)로 환산. 이 값이 크게 떨어지면 문장이 깨질 수 있는 변화

### reward와 margin
log ratio와 reward
- log ratio = policy logp - reference logp : 학습으로 그 답의 확률이 기준보다 얼마나 변했는지
- reward = beta * log ratio
- reward는 사람이 준 점수가 아님. 기준에서 변한 양을 beta로 스케일한 값
- 양수 : 기준보다 그 답의 확률이 올랐다, 음수 : 내려갔다

margin
- margin = chosen reward - rejected reward
- chosen의 변화가 rejected의 변화보다 얼마나 더 유리한가의 차이. beta는 이미 reward에 곱해져 있음.
- 학습 시작 시점에는 policy = reference라서 margin 0

### loss와 시그모이드
시그모이드 σ
- 어떤 실수든 0과 1 사이의 값으로 바꿔 주는 함수. 0이면 0.5, 크게 양수면 1에 가까워짐
- DPO에서는 margin을 (chosen을 선호할 확률)로 읽는 데 쓰임

손실
loss = -log σ(margin)
- margin이 클수록 σ가 1에 가까워져 loss가 작아짐
- 시작 시점 margin 0이면 σ=0.5이고, loss = -log0.5 = ln2 ≈ 0.693. DPO 학습 초기에 확인해야 할 기준 값

margin의 함정
- margin은 두 reward의 차이만 봄. 그래서 같은 margin이 서로 다른 상황에서 나올 수 있음.
    - 바라는 모양 : chosen은 그대로, rejected만 내려감 -> margin 상승
    - 위험한 모양 : chosen도 내려가는데 rejected가 더 많이 내려감 -> margin 상승
- 둘의 loss가 같기 때문에, loss와 margin만으로는 좋은 답이 망가졌는지 알 수 없음. chosen 쪽 값을 따로 봐야 함

beta와 learning rate
| |beta|learning rate|
|---|---|---|
|비유|채점 기준(눈금)|보폭|
|위치|손실 식 안(reward=beta*log ratio)|optimizer 안|
|바꾸면|reward/margin/loss의 눈금과 기울기가 달라짐|갱신 한 번의 가중치 이동량이 달라짐|

gradient accumulation (기울기 누적)
- 한 쌍씩 처리하고 기울기를 모아서, 여러 쌍이 쌓이면 한 번에 갱신. 메모리 때문에 큰 배치를 못 쓸 때 배치를 크게 쓴 것 같은 효과를 냄
- 갱신 횟수 계산 : 쌍 수 * epoch 수 / 누적 수 

clip_grad_norm(기울기 자르기)
- 기울기 벡터의 크기(노름)가 기준보다 크면 그 기준으로 줄여서 한 번의 갱신으로 가중치가 크게 튀는 걸 막음.
- 가중치 값을 자르는게 아니라 기울기 크기를 제한하는 것. 갱신 전의 기울기 크기가 기록될 때는 기준보다 크더라도 이상한 게 아님.

### 과최적화
과최적화 (over-optimization)
- 목적함수(loss, margin)는 잘 갈성했는데, 정작 원하던 행동은 망가진 상태

DPO에서 생기는 이유
- margin은 차이만 보기 때문에, chosen의 확률이 같이 내려가도 rejected가 더 많이 내려가면 목적이 달성됨.
- 학습률이 크거나 기준(reference)에서 너무 멀리 가면, chosen이 내려가서 문장 자체가 깨질 수 있음.

증상
- loss가 0에 붙고 margin이 매우 커지는데, chosen이 logp가 크게 음수로 떨어짐
- 생성된 답이 문법이 깨지거나, JSON 구조가 무너지거나, 여러 언어가 섞임
- 이전에 안 하던 새로운 실수가 나타남

확인하는 법
- loss와 margin만 보지 말고 chosen reward를 따로 봄. 0 근처면 좋은 답을 지킨 것이고, 크게 음수면 위험 신호
- loss, margin, chosen 세 곡선을 같이 봄
- 생성된 원문을 직접 읽음

일반적인 대응 방향
- 학습률을 낮춤, 갱신 횟수 줄이기
- beta 조정
- 선호 데이터의 품질과 구성을 점검

### 결과를 해석하는 법
학습한 쌍의 점수 vs 안 배운 질문의 생성
- 학습한 쌍의 점수 : 학습 데이터 쌍의 margin, logp가 학습 후 어떻게 변했는지
- 안 배운 질문의 자유 생성 (free generation) : 학습에 쓰지 않은 질문에 모델이 실제로 답을 써 보게 해서 보는 것
- 학습한 쌍의 점수가 좋아도 새 질문의 생성은 망가질 수 있어서 둘을 따로 읽음

margin 양수의 의미
- margin이 양수라는 건 "기준보다 차이가 나아졌다"는 방향일 뿐, chosen이 rejected보다 확률이 더 높다는건 아님
- margin 양수는 정답이 아니라 방향

### 과잉 보류와 근거 없는 단정
과잉 보류 (over-abstention)
- 근거가 충분해서 답할 수 있는 질문에서 "확인할 수 없습니다"처럼 보류하는 것

근거 없는 단정
- 근거가 부족한 질문에서 보류하지 않고 그럴듯하게 답해 버리는 것

숫자를 읽을 떄의 함정
- 과잉 보류 0건이 좋은 소식처럼 보여도, JSON이 꺠져서 status 필드를 읽지 못한 답은 집계에서 빠짐
- 형식 통과 ≠ 판단 맞음 : JSON 구조를 통과해도 내용이 무의미할 수 있음
- 집계가 보는 건 status 같은 구조적 필드 뿐이고, 금액 비교가 맞는지나 이유가 옳은지는 채점하지 않음

W&B (Weights & Biases)
- 학습 중 기록된 loss, margin 같은 값을 곡선으로 모아 보고, 여러 실행을 겹쳐 비교하는 실험 관리 도구
- 여러 학습률 실행을 한 화면에 겹치면 chosen이 무너지는 실행을 한눈에 찾을 수 있음
