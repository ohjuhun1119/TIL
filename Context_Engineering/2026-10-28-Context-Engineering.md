## 배운 내용

### Context Engineering : 모델이 한 번의 요청에서 참고할 모든 입력을 구성하고 관리하는 일  

### Prompt Engineering, RAG, Context Engineering 차이점  
Prompt Engineering : 모델에게 어떻게 지시하고 어떤 형식으로 답하게 할지 다룸  
RAG : 요청에 필요한 문서를 찾아 근거로 가져오는 방법을 다룸  
Context Engineering : 찾은 문서와 다른 정보까지 포함해 무엇을, 어떤 순서와 범위로 모델에 전달할지 관리  

자료의 종류(kind) : 무엇을 담은 정보인지 나타냄 / 규정 문서, 도구 조회 결과, 메모리  
메시지 역할(role) : 대화에서 어떤 위치인지 나타냄 / system, user, assistant, tool  

자료 선택 기준  
1. 접근 범위 : 현재 사용자나 조직이 읽을 수 있는가
2. 유효성 : 지금 적용 중인 자료인가? 만료되거나 폐기되지 않았는가?
3. 일관성 : 다른 근거와 충돌하지 않는가?
4. 관련성 : 현재 질문을 푸는 데 필요한가?
5. 예산 : 질문과 답변 공간을 고려했을 때 입력 길이에 들어가는가?  

### 단기 메모리와 장기 메모리  
단기 메모리 : 현재 대화의 예약, 직전 도구 결과, 아직 끝나지 않은 작업처럼 지금 일을 이어 가기 위한 상태. 작업이 끝나거나 세션이 만료되면 더는 필요하지 않을 수 있음  
장기 메모리 : 사용자가 다음 대화에서도 재사용할 수 있다고 확인한 응답 선호나 지속 중인 프로젝트 정보. 목적, 사용자 범위, 보존 기간을 정하고 현재도 유효한지 확인  

입력 예산 = 요청 한도 - 출력 예약량 - 여유분  
출력 토큰 공간을 너무 적게 남기면 모델이 답변을 충분히 이어 가지 못할 수 있음  

최근 대화를 남길 때는 턴 단위로 : 메세지 몇 개로 자르면 한도를 보장하지 못하기 때문에 질문과 대답을 한 턴으로 보고 묶어서 확인  

Prompt caching : 여러 요청에서 반복되는 프롬프트 앞부분을 서버가 재사용해, 그 부분을 매번 처음부터 처리하는 비용과 시간을 줄이는 기능  
KV cache : 한 번의 생성에서 이미 처리한 입력의 내부 상태를 재사용  
Prefix cache : 여러 요청에 공통인 입력 앞부분의 처리 결과를 재사용. 공통 입력 처리를 줄이지만, 새 질문에 대한 답변은 다시 생성  
응답 캐시 : 조건에 맞는 과거의 완성 답변을 재사용할 수 있음  

변하지 않는 정책/지시를 앞에 두고 요청마다 달라지는 ID와 질문을 뒤에 두는 구성이 유리  

### 오염과 Prompt Injection 방지  

Prompt Injection : 사용자 입력이나 문서 같은 자료 안에, 모델이 원래 따르던 지시를 무시하거나 다른 행동을 하도록 유도하는 문장을 넣는 공격

컨텍스트가 잘못되는 원인  
1. 권한이 없는 조직의 자료가 포함됨
2. 폐기되거나 만료된 규정을 사용함
3. 메모리나 요약이 과거 상태를 현재 사실처럼 전달함
4. 문서/웹페이지/메일 안의 문장이 지시나 도구 행동을 바꾸려 함

해결 방안 
1. 실행 전에 사용자의 권한, 허용된 도구, 인자 형식과 범위를 검사  
2. 자료와 지시 구분
